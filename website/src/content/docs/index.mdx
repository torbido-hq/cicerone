## Features

- **Batch job** — cron-scheduled train and top-K write (dataset or DB I/O)
- **Hybrid strategies** — LightFM, item KNN, optional SASRec/BERT4Rec/HSTU, content cold-item fallback, popular, latest; priority, RRF, or per-user blending
- **Serve mode** — read-only HTTP API over precomputed recommendations, including optional `reasons` (why this item); OpenAPI at `/docs`
- **Incremental events** — write-through of popular/latest between retrains; optional `[events.online]` continues LightFM for affected users
- **A/B experiments** — sticky user assignment across ranking recipes; sequential CIs, catalog guardrails, dashboard promote
- **Policies & AutoML** — eligibility filters, score boosts, time-fold backtests
- **Ops** — retrain webhook, optional input poll, Prometheus metrics, Basic-Auth dashboard with user-id lookup
- **Install** — Docker image, or `pip install cicerone-recommender` (`cicerone` CLI)

## Flow

Input (dataset or database) → weigh interactions → train strategies → write top-K recommendations → optional serve API / dashboard.

## Dashboard

Standalone status page for the latest job run (and history with a DB output), plus a user-id lookup of current top-K recommendations and an Experiments page for recipe A/B tests. HTTP Basic Auth; never loads the training stack.
